# YouTube Music ID 변경 — 복구·검증 현황

2026-09-15 · **DB 복구·후속 5건과 11개 목록 전체 게시 검증 완료. 교정 history는 로컬 설치를 마쳤고, 공개 배포 검증과 실제 일간 재실행이 남아 있다.**

현재 게시 제품은 `5f39fb52112c84a12706a83a89881325fcaef397`, 구현 지문은 `9d04d5d4a1c964b653a03363c62f8770ac7917cc8674370c9455c68d758afffe`다. 이미 적용한 DB 명세와 출력을 유지하고 감사 기록 보존을 강화한 코드로 게시했다. 이전 시점의 보류 사유와 시험 결과는 [기존 보고서](../YTMusic_ID_Stability_Final_Verification.md)에 보존한다. 현재 선택과 진행 상태는 이 문서를 기준으로 읽는다.

## 원인과 재발 방지

9월 13일에는 월요일 전용 주간 작업을 건너뛰었고 14일에는 실행했다. 당시 제품 코드와 라이브러리 버전은 같았지만, 주간 차트의 영상·음원 관계를 반영하는 경로에서 기존 정상 대표 ID가 바뀌었다. 저장·후처리 단계에서도 최신 변경 시각이나 관계 정보가 기존 선택을 덮을 수 있었다. 공개 응답의 로그인·Premium 요구를 실제 재생 불가와 혼동하는 문제도 분리했다.

이제 정상 기존 ID를 보존하고, 변경하려면 정확한 곡·버전과 인증 환경의 재생 가능성을 각각 확인한다. 불확실한 응답은 자동 교체나 곡 누락의 근거로 사용하지 않는다. 수집·매칭·필요한 정리를 마친 뒤 동일한 확정 결과로 목록과 history를 만든다. 실제 목록 변경은 요청, 성공 응답, 항목 토큰과 재조회를 연결해 검증한다. 누락 곡 추가를 먼저 검증한 후 기존 항목을 제거하도록 보강했다.

실제 운영 시험에서는 **추가 요청과 성공 응답의 ID가 같아도 YouTube Music이 목록에서 다른 ID를 노출하는 현상**을 확인했다. 원본 player가 정상이라는 사실만으로 목록의 언어·버전까지 같다고 판단할 수 없다. 일반적인 길이 허용치를 늘리거나 모든 counterpart를 같은 녹음으로 허용하지 않았다.

후속 게시 중에는 새 감사 기록을 만들면서 실행한 **31일 보존기간 정리**가 과거 감사 항목을 삭제해, 승인한 저장소 기준과 달라지는 문제도 발견했다. 보호 검사는 실제 목록 전송 전에 이를 차단했다. 삭제된 감사 항목 1,300개를 정확히 복원하고 13개 검사를 통과했다. 공통 `record_playlist_update`는 활성 또는 유효하지 않은 복구 사건이 있으면 과거 감사 삭제·압축만 보류하고 새 감사는 계속 기록한다. 복구 완료 후에는 기존 31일 정리가 다시 적용된다.

새 보호 코드의 사용은 명시적 `execution_release`로 승인한 기존 명세, 적용 영수증의 불변 부분, 출력, 이전·새 구현 지문에 묶었다. 명세를 다시 쓰거나 DB 복구를 재적용하지 않는다. 현재 저장 상태, 미완료 작업, 출력 범위와 최신 재생 검증은 그대로 유지한다.

Hype 게시에서는 8곡 추가·8곡 제거·7회 이동의 성공 응답을 기록한 뒤, 다음 이동 전 관측이 예상 항목 상태와 달라 보호 중단됐다. 이후 두 번의 읽기에서 기존 성공 응답으로 재구성한 100개 항목·토큰·순서가 동일하게 확인됐다. 기존 명시적 복구 경로로 남은 한 곡을 100위에서 68위로 이동하여 2026-09-15 14:01:31 UTC에 해당 목록의 요청 순서를 완료했다. 재개 직전 100개 토큰과 기존 감사 이벤트 18개를 모두 보존했다. 실패 당시 응답 전문은 없어 서버 내부 원인을 단정하지 않는다. 이후 전체 11개 목록의 최종 게시 검증을 통과했다.

후속 5건은 기존 복구를 조정하는 명세다. 꿈, RASEN Acoustic, Brain Rot, 유리의 숲은 정확한 영상·음원 또는 공연 관계를 검토해 Music에서 유지되는 대표 ID를 선택했다. DAY BY DAY는 사용자가 일본어 게시가 안 되면 한국어 게시를 허용한 결정에 따라, **해당 source의 현재 연결만 기존 한국어 UID로 선택**했다. 수동 선택의 canonical ID는 `NULL`이며 언어 선호 키를 추가하지 않았다. 일본어·한국어 곡과 영상 별칭은 각각 유지하고 같은 녹음으로 병합하지 않는다.

제보한 다섯 곡의 복구 선택은 아래와 같으며 인증 진단과 전체 게시 검증을 통과했다. 처음 바뀐 ID 중 정상인 ID도 있었으므로, ID 변화 전체를 재생 불가 건수로 집계하지 않는다.

## 과거 기록과 남은 완료 조건

곡 제외 없이 **11개 목록·1,044개 항목**의 복구 게시를 검증했다. 공개 history 복구의 출발점은 SHA `0cbd2b70…`의 **31일·5,978행**이다. 원래 17건에 해당하는 24행 정정과 추가 원본 7개의 137개 곡·날짜 교정을 부모 24건 미리보기에 반영했다. 이 과정에서 IF YOU의 공연·스튜디오 기여가 섞인 9일을 분리해 9행을 추가하므로 **전체 공개 복구 목표는 31일·5,987행**이다. 기존 점수 정책에 따라 필요한 파생 점수·순위도 교정한다.

후속 명세는 이 부모 미리보기의 교정을 모두 유지하면서, 동일 녹음·공연을 확인한 **4곡의 97행을 추가 교정**한다. 후속 단계에서는 순위·점수·원본 관계와 곡 연결을 유지하고, 앞선 복구에서 일본어 원본으로 분리한 DAY BY DAY 31행도 그대로 둔다. 제보 5곡은 원래 공개 파일에서 각각 잘못 교체된 ID 1일·정상 ID 30일이었으며, 부모와 최종 미리보기 모두 잘못 교체된 ID 0일·정상 ID 31일로 교정됐다. 단계별 수정이 겹칠 수 있어 변경 행 수를 단순 합산하지 않는다.

교정본의 로컬 설치와 승인 해시 일치는 확인했으며, 공개 파일 적용 완료는 별도 검증 중이다. 이전 격리 실행의 history 행이 같아도 생성 시각 때문에 파일 바이트 전체가 같은 것은 아니다.

현재 [로드맵 §9·§10](../YTMusic_ID_Stability_Roadmap.md)의 단계별 완료 조건은 다음과 같다.

- **완료:** 재발 방지 배포, 회귀·인증 진단, 후속 명세의 격리 PG 검증, 운영 DB commit 및 재조회, 과거 감사 자료 복원과 보존 보강, 11개 실제 목록 전체 검증, 교정 history 로컬 설치.
- **진행 중:** 교정 history의 공개 해시 확인, 이후 실제 일간 동기화 재실행 검증. 현재 화요일 일정은 6개 수집·7개 게시이며, 전체 11개 복구 게시와 구분한다.
- **미관측:** 향후 일간·월요일 예약 실행, 실제 기기의 오디오 재생. API 판정을 실제 청취 확인으로 표시하지 않는다.

미완료 incident를 알리는 Actions 오류는 전체 출력 검증 전 정상 게시를 막는 보호 장치다. 이를 상태값만 바꿔 해제하지 않는다. 원래 부모 24건과 후속 5건의 유효 범위, 모든 목록과 공개 history가 함께 검증되어야 정상 실행을 재개하며, 재개 후 결과는 별도로 기록한다. 상세 복구 범위와 실패 이력은 [로드맵](../YTMusic_ID_Stability_Roadmap.md)에 연결한다.
